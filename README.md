# Blink for Android и Android TV

Android-клиент панели Vokop и персональный лаунчер с разделом **Сетевые настройки**.

- Подключение/отключение туннеля пультом, подписка, выбор профиля, срок действия и обновление ссылки.
- VK TURN через явно выбранный TCP или UDP → DTLS → KCP → smux → VLESS. TCP используется по умолчанию. Отдельный ручной **прямой UDP** режим проверяет сервер без VK. Автоматического перехода между режимами нет.
- Диагностика различает готовность транспорта и успешный HTTPS-запрос через Android VPN; показывает счётчики, внешний IP и длительность DNS, TCP IPv4, TLS и ожидания ответа.
- Wi-Fi/Ethernet и локальная IPv4-сеть остаются доступны. VPN не стартует при загрузке ТВ. До готовности транспорта VPN не создаётся. CAPTCHA проходит вручную через официальный SDK VK в обычной сети; результат продолжает тот же запрос. Ожидание проверки ограничено 5 минутами. При отсутствии соединения 45 секунд подключение останавливается.

`app/` — клиент `com.remzone.blink.tv`, `launcher/` — обновление персонального `com.gathin.tvhome`. Лаунчер не получает INTERNET и ключи подписки. Он читает состояние и переключает сервис через provider с permission уровня signature. Оба APK должны быть подписаны одним ключом.

В версии 0.3.1 VPN использует IPv4. Неработающий IPv6-путь на стенде давал длительные TLS-таймауты, поэтому IPv6-адрес, маршруты и DNS удалены из VpnService. IPv6 блокируется Android для этой VPN-сети, а не выпускается в обход туннеля; IPv6-only ресурсы пока не поддерживаются. Поддержку IPv6 нужно возвращать после отдельной проверки выхода сервера. Поведение семейства без адреса/маршрута/DNS описано в [Android VpnService.Builder](https://developer.android.com/reference/android/net/VpnService.Builder#allowFamily(int)).

Android 8.0+ / API 26+, сборки ARMv7, ARM64 и x86_64. На узком экране карточки расположены вертикально; ориентация телефона не фиксируется. На широком экране используются две колонки, на ТВ поддерживается пульт.

**Фактическая проверка устройств: только Android TV. Обычный Android (телефоны/планшеты) адаптирован и собирается, но реальные проверки на телефоне и телефонном эмуляторе не выполнялись.**

## Сборка

Нужны JDK 17, Android SDK 34, Build Tools 34.0.0, NDK 27.2.12479018, Go 1.27.x. Версии Go-зависимостей и gomobile закреплены в `native/go.mod` и `go.sum`; Gradle wrapper — 8.9, AGP — 8.5.2.

```bash
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/27.2.12479018"
export PATH="$JAVA_HOME/bin:/path/to/go/bin:$PATH"
# Для обновления существующего лаунчера используйте прежний signing key.
# Текущая локальная сборка обоих модулей использует debug.keystore из ANDROID_USER_HOME.
export ANDROID_USER_HOME=/path/to/existing/android-user
./tools/build.sh
(cd native && go test -race ./...)
```

Скрипт создаёт локальный `native/blinkcore.aar`, выполняет unit tests, lint и сборку обоих APK:

```
app/build/outputs/apk/release/app-armeabi-v7a-release.apk
app/build/outputs/apk/release/app-arm64-v8a-release.apk
app/build/outputs/apk/release/app-x86_64-release.apk
app/build/outputs/apk/release/app-universal-release.apk
launcher/build/outputs/apk/release/launcher-release.apk
```

APK, AAR, signing key, кеши, реальные подписки и отчёты с идентификаторами устройств исключены из Git. GitHub Actions и GitHub Releases не используются. Для распространения вне личного стенда настройте собственную release-подпись в обоих модулях; сохраните прежний ключ для обновления уже установленного Home.

## Установка и первый запуск

```bash
adb -s TV_ADB_ADDRESS install -r app/build/outputs/apk/release/app-armeabi-v7a-release.apk
adb -s TV_ADB_ADDRESS install -r launcher/build/outputs/apk/release/launcher-release.apk
```

Выберите APK под ABI устройства (`adb shell getprop ro.product.cpu.abi`); universal содержит все ABI. Лаунчер устанавливается только на ТВ, на телефоне достаточно клиента. `tools/install-tv.sh` выбирает ABI автоматически и проверяет совпадение подписей.

Не удаляйте установленный лаунчер: `install -r` с прежней подписью сохраняет настройки, оформление и историю. Перед обновлением сохраните текущий APK. Смена Home, отключение системных приложений и перезагрузка для установки не нужны.

Откройте сетевую кнопку лаунчера → «Подписка и профили Vokop» → «Добавить / заменить ссылку». Нужна scoped HTTPS-ссылка вида `https://panel.example.org/vokop-panel/api/vokop/v1/subscriptions/TOKEN` из панели. Затем выберите режим, нажмите «Подключить туннель» и подтвердите системное разрешение VPN. «Проверить интернет через туннель» выполняет HTTPS-запрос к Cloudflare trace; внешний IP должен соответствовать выходу сервера.

При долгом открытии сайтов отключите туннель, выберите **VK: TCP / UDP**, подключитесь снова и сравните «Проверить интернет через туннель» в обоих вариантах. UDP здесь — транспорт **до VK TURN**, он не включает прямой диагностический режим и не обходит VK. Автоматического переключения нет; если UDP недоступен в вашей сети, верните TCP. Настройка хранится на устройстве и сохраняется при обновлении подписки.

Проверка выполняет небольшой HTTPS-запрос через выбранную Android VPN-сеть с проверкой сертификата. Для сопоставимости выбирается IPv4; это не проверка IPv6 и не замер пропускной способности. DNS, установление TCP, TLS и ожидание первого байта измеряются отдельно. TCP здесь включает ответ локального пакетного стека VPN, поэтому его время не равно RTT до сайта. Для сетевых задержек сравнивайте прежде всего DNS, TLS и ответ. Ошибка показывает этап; по одному замеру нельзя определить причину задержек всех приложений.

Ссылка и документ подписки шифруются AES-GCM ключом AndroidKeyStore; резервное копирование и перенос исключены. Административный пароль панели клиенту не нужен. Экран показывает срок и версию подписки; денежный баланс панель этим API не отдаёт.

## Ограничения протокола

VK может запросить CAPTCHA при выдаче TURN-реквизитов. Нажмите «Пройти проверку VK» в клиенте или сетевых настройках лаунчера. Современную проверку открывает официальный VK ID CAPTCHA SDK 0.0.16; старый формат с изображением принимает код вручную. Автоматического решения CAPTCHA нет.

На ТВ: стрелки двигают курсор, OK нажимает, ▶/пауза или Меню включает/отпускает удержание для ручного перетаскивания. Назад закрывает проверку, затем можно повторить её или отменить подключение. На телефоне используется сенсорный экран.

Установленное приложение VK не передаёт Blink свои cookies или авторизацию. Для этой проверки используется официальный CAPTCHA SDK; собственная регистрация приложения в VK ID и SSO здесь не настраивались. Успешное прохождение страницы ещё проверяется повторным запросом VK; само по себе оно не означает готовность TURN или успешный VPN-трафик. Прямой режим доказывает работу сервера и Android VPN, но не прохождение трафика через VK.

Сохранена совместимость с сервером `vk-turn-proxy` на commit `e8a96967dc66f3dbd631596ea6a8b9fe03f9be69`: upstream DTLS не проверяет подлинность сертификата сервера, внутренний VLESS использует `encryption=none`. Это экспериментальный транспорт; не следует считать его заменой аутентифицированному сквозному TLS. HTTPS приложений продолжает проверять сертификаты самостоятельно.
