# Архитектура

Android VpnService создаёт TUN только после готовности транспорта; отдельный поток читает неблокирующий дескриптор через poll и передаёт IP-пакеты в gomobile Engine.Input. Go использует пакетный стек Xray, а выходящие пакеты возвращает в TUN. Внешние сокеты VK, DNS, TURN и direct UDP защищены VpnService.protect, иначе они попали бы обратно в VPN.

За туннель направляются публичные IPv4 и IPv6; IPv4 LAN, loopback, link-local и multicast остаются локальными. DNS приложения отправляется через VPN. Bootstrap DNS ядра защищён от захвата VPN. VPN не требует root, always-on или отключения штатной сети.

## Транспорт и диагностика

Настройка устройства `turnTransport` принимает только `tcp` и `udp`; без неё используется TCP. Она проходит из зашифрованных настроек в mobile.VKProfile и vkturn.Config. Для UDP используется защищённый connected UDP socket, для TCP — STUN framing поверх защищённого TCP socket. Адрес TURN выдаёт VK, DTLS/KCP/smux и серверная совместимость не меняются. Ошибка UDP не включает TCP или прямой режим автоматически.

Диагностический HTTPS-запрос использует DNS и SocketFactory конкретной активной Android VPN-сети. После ответа проверяется, что та же VPN-сеть остаётся активной. Сертификат проверяется системным SSLSocketFactory с HTTPS hostname verification. Из DNS-ответа выбирается IPv4, затем отдельно измеряются подключение TCP, TLS и время до первого байта HTTP. Это малый запрос, не speed test; IPv6 этим запросом не оценивается.

## Подписка

Только `vokop.subscription.v1`: `revision`, `issued_at`, `expires_at`, непустой `profiles`. Профиль содержит `id`, `name`, `vless.uuid`, `turn.peer_host`, `peer_port`, `vk_call_url`, `streams`. Принимаются vk.com/vk.ru и www с HTTPS `/call/join/TOKEN`. Числа проверяются по типу и диапазону, JSON — на дубли ключей и неоднозначные расширения. Истёкшие, чрезмерно длительные и откатившиеся по revision документы не применяются.

Подписка загружается по HTTPS без редиректов и с проверкой системной цепочки сертификатов. Сохранённая revision относится к конкретной ссылке. При обновлении активная сессия перезапускается, чтобы применить новый срок/профиль. Истечение срока останавливает ядро. «Забыть подписку» отключает VPN и удаляет сохранённый документ.

## Лаунчер

`content://com.remzone.blink.status/state` доступен только приложениям с той же подписью через `com.remzone.blink.permission.STATUS`. Query отдаёт состояние, режим, имя профиля, срок, revision, счётчики и результат проверки. Ссылка подписки и UUID отсутствуют. `call("toggle")` также отдельно проверяет signature permission. Когда требуется системное разрешение VPN, лаунчер открывает клиент; тот вызывает обычный VpnService.prepare.

Home подписывается на ContentObserver только пока открыт экран настроек. Native runtime и сетевые операции остаются в клиенте. При отсутствии клиента или несовпадении подписи штатные Wi-Fi/Ethernet настройки доступны.

## Состояния

`connecting` — транспорт устанавливается; `ready` — создана smux-сессия. Это ещё не доказательство доступа к сайтам. Отдельный HTTPS probe требует активной сети с TRANSPORT_VPN до и после запроса. При `captcha_required` TUN закрывается, а Go-сессия с исходным HTTP-клиентом, cookie jar и запросом сохраняется до 5 минут. Приватное API Engine.CaptchaJSON отдаёт challenge только UI клиента. Официальный SDK возвращает success_token (либо пользователь вводит ключ старой CAPTCHA); SubmitCaptcha привязывает одноразовый ответ к случайному ID, типу и сроку. Повторяется исходный VK-запрос с его access_token и cookie jar, а не новая анонимная сессия. После готовности транспорта сервис снова создаёт TUN. При 45 секундах без готовности вне ручной проверки подключение закрывается. Прямой UDP выбирается только вручную; автоматического fallback нет.

## CAPTCHA и формы устройств

Challenge URL допускается только на HTTPS vk.com/vk.ru или их поддоменах, без userinfo, нестандартного порта и fragment. Он, success_token и код CAPTCHA остаются в памяти процесса; они не передаются через Intent, provider, журналы или Git. SDK хранит свой краткоживущий результат в памяти. Ожидающий запрос удаляется при отмене, остановке ядра, смене подписки и по сроку; при смерти процесса подключение начинают заново.

Provider сообщает лаунчеру только флаг pendingCaptcha; challenge и ключи остаются приватными. Телефонные карточки складываются при ширине менее 700 dp, на широком экране сохраняются две колонки. Полноэкранный режим и курсор пульта включаются только при UI_MODE_TYPE_TELEVISION. Курсор отправляет события только WebView собственного окна VK SDK; глобальная инъекция ввода и accessibility service не используются.

VK ID CAPTCHA SDK выполняет ручную проверку запроса, а не SSO через установленный VK-клиент. Сессии других приложений не извлекаются.
