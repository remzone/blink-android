# Проверка 2026-11-06

## Версия 0.3.1: не объявлять неработающий IPv6

- **Проверка владельцем на ТВ после установки 0.3.1 с активным VK TCP:** приложения стали заметно быстрее. Это качественная оценка владельца, а не замер всех приложений; отдельное наблюдение UDP DNS-повторов остаётся открытым.

- На ТВ через активный VK TCP VPN временная ARM-утилита с проверкой системных CA выполнила HTTPS по IPv4: HTTP 200, IP выхода сервера, 670 и 776 мс.
- Та же утилита дважды принудительно выбрала IPv6: DNS вернул AAAA, но TLS завершился таймаутом около 6 секунд (6141 и 6140 мс вместе с DNS). Это доказанный отказ IPv6-пути в текущей конфигурации; он не устанавливает, находится ли первопричина в ядре, сервере или его сети.
- VpnService больше не добавляет IPv6-адрес, маршруты или DNS. IPv6 блокируется средствами Android, обход через underlying network не разрешается. Это позволяет приложениям использовать рабочий IPv4 вместо попыток через объявленный, но неработающий IPv6. IPv6-only ресурсы пока недоступны.
- Клиент 0.3.1: 13 unit tests без ошибок, Android Lint 0 ошибок, release APK для трёх ABI и universal собраны. Обновление на ТВ выполнено с сохранением подписки. Телефон и эмулятор не проверялись.
- После новой ручной CAPTCHA установлен VK TCP. `dumpsys connectivity` показывает IPv6 `::/0 unreachable`, IPv6-адрес и IPv6 DNS у VPN отсутствуют. Принудительный IPv6-запрос теперь завершается `no route to host` без TLS-ожидания: 224 мс вместе с DNS. IPv4 HTTPS: HTTP 200, выход сервера, 648 и 677 мс. Повторный IPv6-тест потратил 5151 мс на DNS и затем сразу отклонил соединение; IPv6 TLS больше не запускается.
- Встроенный Android HTTPS probe после исправления: успешный выход сервера, 1492 мс (DNS 451, TCP 2, TLS 381, первый байт 653).
- **Оставшееся наблюдение:** standalone Go resolver в двух UDP DNS-проверках дал повторную попытку около 5 секунд (один автоматический выбор, один AAAA lookup); остальные UDP DNS около 133–224 мс. С DNS поверх TCP три проверки дали 208–224 мс без повторов. Этого недостаточно, чтобы установить причину или считать проблему DNS исправленной. Никакой подмены Android DNS на системный/прямой обход VPN не выполнено.
- Автоматический выбор семейства в standalone probe: HTTP 200 через сервер за 766 и 897 мс в успешных быстрых запросах. Ранее один запрос занял 5797 мс из-за 5138 мс в DNS. Это разные измерения и не обещание одинаковой задержки во всех приложениях.

## Версия 0.3.0: сравнение TURN TCP/UDP и этапы HTTPS

- Добавлен явный выбор TCP/UDP до VK TURN. TCP по умолчанию, автоматического перехода между транспортами или в direct нет. Серверный DTLS/KCP/smux/VLESS протокол сохранён.
- `go test -p 2 -race ./...` проходит. Новый тест поднимает настоящий локальный Pion TURN для каждого транспорта и передаёт данные через TURN → DTLS → KCP → smux; проверяет вызов socket protector. Это локальный тест, не замер сети VK.
- HTTPS probe привязан к активной VPN-сети, проверяет сертификат и показывает DNS, TCP IPv4, TLS и время до первого байта. Парсер ответа проверяется на Content-Length/chunked, ошибки статуса, усечение и ограничения размера.
- Клиент: 13 unit tests, ошибок нет; Android Lint — 0 ошибок; release APK собраны для ARMv7, ARM64 и x86_64, а также universal.
- Версия 0.3.0 установлена поверх 0.2.0 на реальном 32-битном Android TV; подписка сохранена, выбор TCP/UDP отображается и сохранённый UDP восстанавливается после перезапуска клиента.
- На ТВ HTTPS через прямой DTLS/VLESS VPN подтверждён дважды: внешний IP сервера, RX/TX растут. Замеры: 943 мс (DNS 499, TCP 2, TLS 293, первый байт 145) и 965 мс (DNS 448, TCP 2, TLS 198, первый байт 316). Это отдельные запросы, не speed test и не проверка инфраструктуры VK.
- После ручного прохождения настоящей CAPTCHA на ТВ VK UDP перешёл в ready и передал реальный HTTPS-трафик через сервер. Два запроса: 852 мс (DNS 501, TCP 2, TLS 206, первый байт 142) и 358 мс (DNS 2, TCP 1, TLS 211, первый байт 143). Второй DNS мог использовать кеш; это не независимые холодные замеры.
- После второй ручной CAPTCHA VK TCP тоже передал реальные HTTPS-запросы: 1162 мс (DNS 519, TCP 2, TLS 493, первый байт 147) и 801 мс (DNS 3, TCP 4, TLS 203, первый байт 591). На этих малых IPv4-запросах UDP оказался быстрее; двух запросов недостаточно для устойчивой оценки транспорта под нагрузкой.
- Фактические испытания только на Android TV. Телефоны, планшеты и телефонный эмулятор не проверялись.
- На малом IPv4 HTTPS-запросе через VK UDP сильные задержки не воспроизвелись. Причина прежнего медленного открытия всех приложений и преимущество над TCP пока не подтверждены; IPv6, видео и пропускная способность этими запросами не проверяются.

## Повторение live acceptance

Только на разрешённом сервере. Создайте вне Git JSON с полями `mobile.VKProfile` (см. native/mobile/vkturn.go), действующими UUID/ссылкой звонка/сервером/сроком и `mode: "direct"` либо `"vk"`:

```bash
cd native
BLINK_LIVE_PROFILE=/absolute/private/profile.json go test -race -run TestLivePacketStackToServer -v ./mobile
```

Секреты из live-профиля не выводятся. Тест не запускается без переменной. Он не заменяет проверку Android на реальном ТВ.

## Повторение раздельной проверки IPv4/IPv6 на ТВ

`tools/netprobe/main.go` — временная standalone-утилита, не часть APK. Для проверенного ARMv7 Android TV:

```bash
mkdir -p work
CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=7 go build -trimpath -o work/blink-netprobe tools/netprobe/main.go
adb -s TV_ADB_ADDRESS push work/blink-netprobe /data/local/tmp/blink-netprobe
adb -s TV_ADB_ADDRESS shell chmod 700 /data/local/tmp/blink-netprobe
# Сначала включите нужный VPN в клиенте и убедитесь, что он ready.
adb -s TV_ADB_ADDRESS shell /data/local/tmp/blink-netprobe >work/ip-families.jsonl
adb -s TV_ADB_ADDRESS shell rm /data/local/tmp/blink-netprobe
```

Утилита отдельно проверяет A/IPv4, AAAA/IPv6 и автоматический выбор семейства. DNS направлен к 1.1.1.1, сокеты не защищаются от VPN. TLS использует CA из `/system/etc/security/cacerts`; сверяйте внешний IP с сервером и состояние VPN. Вывод содержит IP выхода, сохраняйте его вне Git. Это диагностика shell UID на реальном ТВ, а не тест интерфейса телефона. Таймаут TLS 6 с и общий лимит 12 с на семейство. Системная DNS-политика Android и алгоритм выбора адресов отдельного приложения могут отличаться от Go-утилиты.
