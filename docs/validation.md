# Проверка 2026-11-06

## Версия 0.3.0: сравнение TURN TCP/UDP и этапы HTTPS

- Добавлен явный выбор TCP/UDP до VK TURN. TCP по умолчанию, автоматического перехода между транспортами или в direct нет. Серверный DTLS/KCP/smux/VLESS протокол сохранён.
- `go test -p 2 -race ./...` проходит. Новый тест поднимает настоящий локальный Pion TURN для каждого транспорта и передаёт данные через TURN → DTLS → KCP → smux; проверяет вызов socket protector. Это локальный тест, не замер сети VK.
- HTTPS probe привязан к активной VPN-сети, проверяет сертификат и показывает DNS, TCP IPv4, TLS и время до первого байта. Парсер ответа проверяется на Content-Length/chunked, ошибки статуса, усечение и ограничения размера.
- Клиент: 13 unit tests, ошибок нет; Android Lint — 0 ошибок; release APK собраны для ARMv7, ARM64 и x86_64, а также universal.
- Версия 0.3.0 установлена поверх 0.2.0 на реальном 32-битном Android TV; подписка сохранена, выбор TCP/UDP отображается. Замер VPN на ТВ и сравнение VK остаются незавершёнными.
- Фактические испытания только на Android TV. Телефоны, планшеты и телефонный эмулятор не проверялись.
- Ускорение VK и причина медленного открытия пока не подтверждены сравнительными замерами.

- У официального SDK обнаружена отсутствующая зависимость AndroidX Core; добавлена явно, повторное открытие окна на ТВ успешно.

Дополнительно на ТВ в версии 0.2.0:

- проверка открывается как из клиента, так и кнопкой «Пройти проверку VK» в лаунчере; в окне SDK видны настоящий VK ID challenge и инструкция пульта, стрелка перемещает курсор;
- «Назад» из окна VK возвращает экран повторения/отмены; следующий «Назад» отменяет подключение, foreground service останавливается;
- фактически проверено истечение 5-минутного ожидания: SDK закрывается, сервис завершается, активного VPN нет;

- обновлённый клиент установлен поверх существующего, подписка сохранена.

**Обратная связь владельца после проверки 0.2.0:** CAPTCHA проходится, соединение устанавливается, но всё долго открывается. Это пользовательское наблюдение; независимый замер задержек через VK в этой сессии не выполнен. Повторение исходного запроса проверено детерминированным Go-тестом с ответом-фикстурой. Автоматического решения CAPTCHA в коде нет.

## Базовая версия 0.1.0

## Выполнено локально

- `go test -race ./...`: mobile и vkturn проходят, включая loopback TCP/VLESS и реальный локальный DTLS/KCP/smux обмен с проверкой socket protector.
- `:app:testReleaseUnitTest`: 8 тестов, 0 ошибок. Проверяются строгий JSON, duplicate keys, срок/revision подписки, адреса VK и сохранение LAN-маршрутов.
- `:launcher:testReleaseUnitTest`: 327 тестов, 0 ошибок.
- Android Lint обоих модулей: 0 ошибок; предупреждения о фиксированной горизонтальной ориентации и локализации текста остаются.
- Release APK собраны для ARMv7 и ARM64. Подпись лаунчера совпадает с сохранённым APK с ТВ.
- Прямой режим: новый mobile.Engine передал синтетические IP-пакеты через Xray → DTLS/KCP/smux → реальный сервер → VLESS → example.com и получил HTTP 200 с ожидаемым телом. Счётчики RX/TX увеличились. Это проверка ядра на Linux, не Android VpnService.
- Режим VK с предоставленной действующей ссылкой: VK возвращает CAPTCHA; ядро корректно сообщает `captcha_required`. Прохождение трафика через VK не подтверждено. Opt-in live test явно отмечает этот случай как SKIP, а не как успешный туннель.

## Проверено на ТВ

STARWIND SW-LED43UG403, Android 11/API 30, 32-битный armeabi-v7a. Перед обновлением сохранён прежний APK; установка выполнена через `install -r` с совпадающей подписью. Сохранены оформление, погода и история Home. Из-за нехватки места Android первоначально отказал в установке; системный `pm trim-caches 512M` освободил временный кеш без удаления приложений и их пользовательских данных.

Проверены:

- установка обоих APK и сохранение подписки после повторного обновления клиента;
- импорт действующей scoped HTTPS-подписки с панели, отображение профиля, срока и revision;
- штатный диалог Android VPN и создание TUN;
- direct DTLS-соединение с сервером и растущие RX/TX;
- HTTPS probe из Android через VPN: успешный ответ, внешний IP совпал с сервером, время около 700 мс;
- навигация пультом к диагностике;
- открытие «Сетевые настройки» сетевой кнопкой Home, получение состояния и срока подписки через signature provider;
- отключение и повторное подключение туннеля непосредственно из лаунчера;
- отклонение `content query` и `content call toggle` от shell без signature permission.

На этой прошивке изменение VPN-сети сбрасывает текущую TCP-сессию ADB; повторный `adb connect` восстанавливает её по тому же LAN-адресу. Штатная Wi-Fi сеть остаётся доступна.

VK TURN проверен и на сети самого ТВ: при подключении ядро получило CAPTCHA. Экран показывает «VK требует CAPTCHA», TUN закрыт; `dumpsys connectivity` подтвердил отсутствие активной VPN-сети. Обычная сеть восстановлена, автоматического перехода в direct не было. Прохождение трафика через VK не подтверждено — это внешнее ограничение выдачи TURN-реквизитов, а не успешный VK-тест.

Повторное открытие уже работающего клиента с переходом к подписке проверено; обновление подписки выполняется с пульта. После проверки VPN оставлен отключённым.

Снимки и журналы проверки находятся только в локальном `work/` и исключены из Git.

## Повторение live acceptance

Только на разрешённом сервере. Создайте вне Git JSON с полями `mobile.VKProfile` (см. native/mobile/vkturn.go), действующими UUID/ссылкой звонка/сервером/сроком и `mode: "direct"` либо `"vk"`:

```bash
cd native
BLINK_LIVE_PROFILE=/absolute/private/profile.json go test -race -run TestLivePacketStackToServer -v ./mobile
```

Секреты из live-профиля не выводятся. Тест не запускается без переменной. Он не заменяет проверку Android на реальном ТВ.
